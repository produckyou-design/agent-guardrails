# agent-guardrails

Попросили AI-агента «только поправить отступы», а в итоге изменено 12 файлов?

Функция переименована, дублирующий код «почищен», цикл retry, который месяцами работал стабильно, упрощён. Diff выглядит разумно. Тесты могут даже пройти.

А через несколько дней ломается что-то совсем не связанное с задачей.

`agent-guardrails` — небольшой Git-gate именно для этой проблемы: **не дать AI-агентам менять уже законченный код за пределами текущей задачи.**

Вместо ещё одной фразы в prompt правило становится исполняемым. Если защищённый путь изменён, commit отклоняется.

Без зависимостей. Без API модели. Только Python и Git.

## Тест за 30 секунд

Дайте агенту маленькую задачу:

```text
Исправь только отступы на странице настроек.
```

После завершения:

```sh
git diff --stat
```

Если ожидались два файла, а изменено девять — откройте остальные семь.

Часто там оказывается что-то вроде:

```text
«Переименовано для ясности.»
«Вынесена дублирующая логика.»
«Удалён код, который выглядел неиспользуемым.»
«Соседний код обновлён для единообразия.»
```

Всё звучит разумно. Ничего из этого не просили.

Если ваши diff и так содержат только заказанные изменения, возможно, инструмент пока не нужен.

## Какую проблему он решает

Предположим, этот файл три месяца стабильно работает в production:

```text
src/billing/charge.py
```

Сегодняшняя задача только такая:

```text
Поправить отступы на странице счёта.
```

Агент не знает, почему `charge.py` выглядит немного странно. Он не знает, не появился ли этот branch после реального сбоя шесть месяцев назад. Агент видит код, а не историю, которая сделала его таким.

Поэтому обычно пишут:

```text
Не трогать этот файл.
```

в `AGENTS.md`, `CLAUDE.md`, prompts и комментариях.

Проблема проста: документация объясняет правило, но не заставляет его соблюдать.

`agent-guardrails` превращает:

```text
пожалуйста, не трогай это
```

в:

```text
commit rejected
```

## Как это работает

Готовые пути добавляются в `frozen.json`:

```json
{
  "frozen": [
    {
      "label": "Billing",
      "paths": ["src/billing/charge.py"],
      "reason": "Завершено, работает в production и не входит в roadmap.",
      "what_breaks": "Неверный расчёт всё равно показывает нормальный экран; меняется только сумма.",
      "before_you_touch": [
        "Частичные возвраты находятся в refund.py.",
        "При ошибке откатывается вся транзакция.",
        "Округление валюты определяется один раз на границе."
      ],
      "how_to_verify": "pytest tests/test_billing.py -q"
    }
  ]
}
```

Если агент изменит этот путь и попытается сделать commit, он остановится именно тогда, когда контекст важнее всего:

```text
$ git commit -m "invoice: tidy up rounding"

frozen: FAIL - a frozen path was changed
  src/billing/charge.py
      [Billing] Finished and in production.
      breaks -> Wrong math still renders a normal screen.
      verify -> pytest tests/test_billing.py -q
```

Gate — локальный Python. LLM не вызывается.

Обычная работа проходит. Дополнительный контекст появляется только при пересечении границы.

## Если frozen-файл действительно нужно изменить

Frozen не означает «никогда не менять».

Для законного изменения нужны три строки в сообщении commit:

```text
UNFREEZE: src/billing/charge.py - новый способ оплаты требует ветки здесь
UNFREEZE-IMPACT: ошибка в логике может изменить списываемую сумму
UNFREEZE-ROLLBACK: git revert <sha>, затем pytest tests/test_billing.py
```

Не хватает одной — commit отклоняется.

Потому что «почему сейчас» недостаточно. Перед изменением проверенного кода нужно понимать **что сломается, если вы ошиблись**, и **как вернуться назад**.

## Что меняется на практике

### Маленькие задачи реже превращаются в огромные diff

```text
Запрос:
поправить отступы

Неожиданные дополнения:
переименовать компонент
рефакторить API helper
упростить retry
объединить типы
```

Scope drift становится виден до попадания в основную ветку.

### Странный код сохраняет свою историю

В зрелой кодовой базе всегда есть строки, которые выглядят неправильно, но держат что-то важное. `before_you_touch` показывает причину именно в момент, когда агент пытается перейти границу.

### Review получает приоритет

Если ночной агент сделал 34 commit и только два содержат `UNFREEZE`, сначала смотрите эти два.

### Модель меняется, правило остаётся

Сегодня Claude, завтра Codex, на следующей неделе Gemini. Правило живёт в Git, а не в памяти модели.

## Экономит ли это токены?

Сами gates используют **0 LLM-токенов**. Это локальные скрипты:

```sh
python scripts/check_frozen.py
python scripts/check_git_policy.py
python scripts/check_scope.py
```

Сократить можно дорогую работу, которая появляется после плохого изменения:

- ненужное исследование файлов
- рефакторинг вне scope
- генерацию кода для него
- дополнительные тесты
- поиск причины регрессии
- rollback
- повторное выполнение задачи

Здесь намеренно нет цифры вроде «экономит 37%». Она зависит от того, как часто ваши агенты выходят за пределы задачи.

Это не оптимизатор токенов. Он предотвращает работу, которой вообще не должно было быть.

## Необязательный scope задачи

`check_scope.py` позволяет ограничить задачу разрешёнными путями:

```text
Задача: отступы страницы настроек

Разрешено:
frontend/settings/**
frontend/styles/settings.css

Запрещено:
backend/**
database/**
billing/**
```

Без scope-файла проверка остаётся неактивной.

## Находит и реально брошенную Git-работу

`check_git_policy.py` не просто считает branches. Он использует эквивалентность патчей (`git cherry`), чтобы отличить работу, которой действительно нет в `main`, от уже попавшей туда через squash или rebase.

В исходном проекте «11 несмерженных веток» превратились в «1 ветку с действительно важной незавершённой работой».

## Откуда появился инструмент

Он не был придуман из чистой теории безопасности агентов.

Он вырос из нескольких месяцев работы AI-агентов с реальной production-кодовой базой. Production ломался 60 раз. Каждый случай записывался так:

```text
Symptom   как это выглядело
Cause     почему произошло
Fix       что изменили
Rule      что делать в следующий раз
```

Правила, которые можно было проверять механически, стали этими gates.

В `FAILURE_MODES.md` находятся 28 реальных случаев, из которых они выросли.

## Установка

Linux / macOS:

```sh
git clone https://github.com/produckyou-design/agent-guardrails
./agent-guardrails/install.sh /path/to/your-repo
```

Windows:

```powershell
git clone https://github.com/produckyou-design/agent-guardrails
.\agent-guardrails\install.ps1 C:\path\to\your-repo
```

Диагностика:

```sh
python scripts/doctor.py
python scripts/doctor.py --json
```

Локальный hook можно обойти через `--no-verify`; CI — нельзя. Рекомендуется использовать оба.

## Начинайте с пустого списка

Не замораживайте весь репозиторий.

```json
{
  "frozen": []
}
```

Когда агент впервые «улучшит» уже готовый код, добавьте этот путь.

Gate, который срабатывает постоянно, превращается в шум. Защищайте только действительно завершённый код, который дорого нарушать.

## Дисциплина staging

Избегайте:

```sh
git add -A
git add .
git add -u
```

Лучше явно указывать файлы:

```sh
git add src/thing.py tests/test_thing.py
```

Агент не может безопасно считать, что все изменения в общем working tree принадлежат ему.

## Проверка означает выполнение

`skill/SKILL.md` содержит правила, которые нельзя надёжно определить только по diff.

Прочитать код и сказать «должно работать» — не проверка. Если команда не запускалась, укажите `NOT_RUN`. Если она упала — сообщите об ошибке. Для визуальных изменений проверьте реальный рендер перед завершением задачи.

## Тесты

```sh
python tests/test_gates.py
```

Всего 16 тестов. Они создают настоящие временные Git-репозитории, настоящие commits и запускают gates отдельными процессами вместо mock-поведения Git.

Ошибки, найденные в самих gates, тоже остаются regression-тестами.

## Что входит

- `FAILURE_MODES.md` — 28 реальных сбоев, породивших эти правила
- `skill/SKILL.md` — правила работы агентов
- `check_frozen.py` — защита завершённых путей
- `check_scope.py` — необязательные границы задачи
- `check_git_policy.py` — поиск действительно оставшейся Git-работы
- `check_guardrail_integrity.py` — защита самих guardrails
- `doctor.py` — диагностика установки

## Чего инструмент не делает

Не ищет secrets — для этого лучше gitleaks.

Не ловит общие опасные паттерны — для этого лучше semgrep.

Не заменяет code review.

Не заставляет AI писать более качественный код.

Он делает одну более узкую вещь:

> Не позволяет правдоподобным изменениям вне scope тихо попасть в уже корректный код как обычный commit.

## В одной строке

Это не ещё один prompt:

```text
Пожалуйста, не меняй существующий код без необходимости.
```

Это то, что происходит после того, как агент проигнорировал эту фразу:

```text
commit rejected
```
