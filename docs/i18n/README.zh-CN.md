## 关于 AI 编码代理，没人告诉你的一件事

它们通常不是靠写烂代码把线上搞崩的。

它们是去动了那些本来已经完工的东西。改动在代码评审里看着完全正常，也没有测试
覆盖，因为那段代码一直好好的，没人想过要给它写测试。

实际长这样。下面每一条都真的上线过。

**部署成功了，画面没变。**
改了 CSS，新的 HTML 也发出去了。浏览器继续用缓存里的旧 CSS。流水线是绿的，日志
是干净的，网站是错的。这是最糟的一类故障，因为成功信号照常亮起。

**push 成功了，部署根本没跑。**
提交存在，也在 GitHub 上。部署流程是手动触发的，所以什么都没发生。"推上去了"和
"上线了"被当成同一件事，整整两天。

**一个功能在线上跑着，它的代码不在任何分支上。**
消费方发布了，生产方没有。页面一直在读一个已经没人再写入的文件，把最后一份正常
副本一直供到过期为止。

**那条安全规则在文档里躺了六个月。**
"不要动移动端布局。"写下来了，达成共识了，就放在每个代理都会读的规则文件里。没有
任何东西去强制它。它被持续违反，每个代理都违反，包括刚刚读完那句话的那些。

最后这一条，就是这个仓库存在的全部理由。

> 没有任何东西去读的规则不是保护措施，它只是一张看起来像保护措施的便条。

## 这是什么

两个 Python 文件。只用标准库。没有模型，没有 API，没有服务，没有要装的依赖。

```
check_frozen.py       353 行   锁住已完工的代码
check_git_policy.py   223 行   找出被埋掉的工作
```

它们来自一个真实项目：AI 代理在那里连续几个月往生产环境发代码，把线上弄坏了 60 次。
每一次都被记录下来，其中能变成代码的就变成了这些闸门。这个仓库带的是可以通用的两个，
外加它们背后的 27 起事故。

## 就算其他都不用，这部分也值得抄走

冻结代码很容易。难的是怎么解冻，因为"去问个人"这个答案，碰上凌晨三点还在干活的
代理就撑不住了。

真正管用的是这个。要动一条被冻结的路径，提交信息里必须带三行：

```
UNFREEZE: src/billing/charge.py - 新支付方式需要在这里加分支
UNFREEZE-IMPACT: 算错了画面依然正常，只有金额会变
UNFREEZE-ROLLBACK: git revert <sha>，然后重跑 pytest tests/test_billing.py
```

少一行，提交就被拒绝。

为什么是三行不是一行？因为理由只回答"为什么是现在"。它不回答你错了会怎样，也不回答
别人怎么退回去。而这两个才是凌晨三点真正要紧的问题，也恰恰是最常被跳过的两个。

重点不是走流程。**如果你写不出影响和回滚，那你还没到能解冻它的程度，而你是自己
发现的，不是在生产环境里发现的。** 这个判断会自己从三行里长出来，所以它对代理和
对人一样有效。

## 到底什么变好了

**你不用再逐条审查了。**
代理一夜之间提交了 34 次。其中两次带着 UNFREEZE 行。先读那两次就行。闸门没有让
代理变得更谨慎，而是**让代理主动告诉你它在哪儿偏离了。**

**"调一下间距"不再带回 12 个改动文件。**
你只要了一件事。diff 里除了这件事，还有税额计算的重构，还有一段重试循环的"清理"，
而那段循环存在只是因为上游 API 不稳定。代理不是马虎。**它没办法分辨哪段奇怪的代码
是有原因才奇怪的。** 现在那段代码在被碰到的那一刻会自己说出来。

**那段撑着东西的临时方案不再被"改进"。**
每个代码库里都有一行看起来不对、却撑着什么的代码。大约每个季度就有人把它整理掉，
然后以一种没人会联想到整理的方式坏掉。`before_you_touch` 就是钉在那道篱笆上的牌子，
而且它出现在终端里，不是在一个没人打开的文件里。

**你可以去睡觉了。**
不是因为代理变谨慎了，而是因为你不在的时候它能造成的最坏后果，
**已经被你清醒时写下的那份清单框住了。**

**规则不再取决于有没有人记得。**
"别动移动端布局"是建议。一个过不去的提交是信息。区别不在于礼貌。这两者里，有一个
能在凌晨三点、对一个从没见过你的模型、在它进入你仓库的第一分钟里生效。

## 这东西不做什么

它不衡量提升了多少。这个 README 里没有 benchmark 表格，因为没有诚实的方法做出一张，
而编出来的表格比这两个脚本还不值钱。

它不扫描密钥，也不扫描不安全的写法。gitleaks 和 semgrep 在这方面比这里能提供的
任何东西都强。这个仓库做的是它们不做的那部分。

它不会让代理写出更好的代码。它让一个错误的改动在上线前就显形。这是两个不同的问题，
这里只处理第二个。

它不替代代码评审。它消掉的是评审最不擅长发现的那一类：对本来就正确的东西，做了一个
微小的、看起来合理的、就在旁边的改动。

## 安装

```sh
git clone https://github.com/produckyou-design/agent-guardrails
./agent-guardrails/install.sh /path/to/your-repo
```

Windows：

```powershell
.\agent-guardrails\install.ps1 C:\path\to\your-repo
```

或者把 `gates/*.py` 拷进你的 `scripts/`，装上 pre-commit hook，再加上
`.github/workflows/gates.yml`。本地 hook 可以用 `--no-verify` 绕过，CI 那道不行，
所以两个都要。

从空的冻结清单开始。等哪天代理动了你以为已经完工的东西，再加上第一条路径。
你不用等太久。

## 怎么写一条撑得住的冻结条目

没有理由的路径，下一个需要它的人会直接解冻。让冻结撑住的是 `what_breaks`，因为
解冻的人得知道自己在赌什么。

```json
{
  "label": "计费",
  "paths": ["src/billing/charge.py"],
  "reason": "已完工并在生产运行。不在任何路线图上。",
  "what_breaks": "算错了画面依然正常，只有金额会变。",
  "before_you_touch": [
    "部分退款属于 refund.py，不在这里。",
    "失败时整笔事务回滚。不要削弱这一点。"
  ],
  "how_to_verify": "pytest tests/test_billing.py -q"
}
```

`before_you_touch` 是故障的归宿。里面每一行都应该是用昂贵代价换来的。

## 不要什么都冻

如果冻结覆盖了整个仓库，闸门就变成了狼来了，真正的违规也会跟着噪音一起被忽略。
路线图马上要动的路径，就敞开放着。

来源项目在几百条路径里只冻了 19 条。

## 测试

```sh
python tests/test_gates.py
```

16 个测试。它们在临时目录里建一个真实的 git 仓库，做真实的提交，把闸门当子进程跑。
没有任何 mock，因为要测的正是闸门怎么读取 git。

也覆盖了用昂贵代价换来的那些 bug，包括声明 `src/db/sync-notices.py` 却因为正则吃掉
了连字符，把 `src/db/sync_orders.py` 也悄悄解锁的那一个。

一个主张"验证必须是可执行的"的仓库，应该能先证明自己。把三行规则削弱掉，会有 3 个
测试失败；把连字符处理弄坏，路径那个测试会失败。可以自己试。

## 还包含

`FAILURE_MODES.md` 记录了产生这些闸门的事故，用的是让它们真正有用的格式：

```
症状  当时看起来是什么样
原因  为什么会这样
处置  改了什么
规则  从今往后怎么做
```

判断一件事该不该进这个文件，只有一个标准：**如果我不写下来，我会不会再犯一次？**
会，就写进去，哪怕什么都没坏。真正反复出现的几乎从来不是那些戏剧性的故障，而是
你每次都会踩进去的小圈子。

`skill/SKILL.md` 是面向代理的另一半：与闸门配套的操作规则。闸门抓的是能机械检查
的东西，skill 覆盖剩下的，比如如实汇报你到底跑了哪些验证。
