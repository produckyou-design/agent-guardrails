## AI 에이전트에 대해 아무도 말해주지 않는 것

에이전트는 대개 코드를 못 써서 라이브를 깨뜨리지 않습니다.

이미 완성된 것을 건드려서 깨뜨립니다. 리뷰에서 보면 지극히 정상으로 보이고,
테스트도 없습니다. 잘 돌아가던 코드라 아무도 테스트를 쓸 생각을 안 했으니까요.

실제로 이렇게 생겼습니다. 아래는 전부 실제로 나갔던 것들입니다.

**배포는 성공했는데 화면이 안 바뀌었습니다.**
CSS를 고쳤고 새 HTML이 나갔습니다. 브라우저는 캐시된 예전 CSS를 계속 썼습니다.
파이프라인은 초록불, 로그도 깨끗, 사이트만 틀렸습니다. 가장 나쁜 종류입니다.
성공 신호가 울리니까요.

**push는 됐는데 배포가 안 돌았습니다.**
커밋 있고 GitHub에도 있습니다. 배포 워크플로가 수동이라 아무 일도 안 일어났습니다.
"올렸다"와 "나갔다"를 이틀 동안 같은 걸로 세고 있었습니다.

**라이브에 도는 기능인데 그 코드가 어느 브랜치에도 없었습니다.**
소비자는 배포됐고 생산자는 안 됐습니다. 화면은 아무도 더 이상 쓰지 않는 파일을
계속 읽으면서 마지막으로 정상이던 사본을 보여주고 있었습니다.

**안전 규칙이 문서에 반년 있었습니다.**
"모바일 레이아웃은 건드리지 않는다." 적혀 있었고 합의했고 모든 에이전트가 읽는
규칙 파일에 있었습니다. 아무도 집행하지 않았습니다. 계속 위반됐습니다. 방금 그
문장을 읽은 에이전트도 포함해서요.

마지막 하나가 이 저장소가 존재하는 이유입니다.

> 아무도 읽지 않는 규칙은 안전장치가 아닙니다. 안전장치처럼 보이는 메모입니다.

## 이게 뭔가

파이썬 파일 두 개. 표준 라이브러리만 씁니다. 모델도 API도 서비스도, 설치할
의존성도 없습니다.

```
check_frozen.py       353줄   완성된 코드를 잠근다
check_git_policy.py   223줄   묻힌 작업을 찾는다
```

AI 에이전트들이 몇 달간 프로덕션 코드를 만들고 60번 깨뜨린 실제 프로젝트에서
나왔습니다. 깨질 때마다 기록했고, 코드가 될 수 있는 것이 이 게이트가 됐습니다.
이 저장소에는 다른 프로젝트에도 걸리는 두 개와, 그 뒤에 있는 사건 27건을
실었습니다.

## 나머지를 안 써도 이건 가져갈 만합니다

잠그는 건 쉽습니다. 어려운 건 어떻게 푸느냐입니다. "사람한테 물어봐"라는 답은
새벽 3시에 일하는 에이전트 앞에서 살아남지 못합니다.

되는 방법은 이겁니다. 잠긴 경로를 건드리려면 커밋 메시지에 세 줄이 있어야 합니다.

```
UNFREEZE: src/billing/charge.py - 새 결제 수단 때문에 여기 분기가 필요하다
UNFREEZE-IMPACT: 계산이 틀려도 화면은 정상이고 금액만 달라진다
UNFREEZE-ROLLBACK: git revert <sha> 후 pytest tests/test_billing.py 재실행
```

하나라도 빠지면 커밋이 거부됩니다.

왜 하나가 아니라 셋이냐면, 사유는 "왜 지금"만 답하기 때문입니다. 틀렸을 때 무슨
일이 벌어지는지, 어떻게 되돌아오는지는 답하지 않습니다. 그 둘이 새벽 3시에 중요한
질문이고, 정확히 그 둘이 생략됩니다.

핵심은 서류 작업이 아닙니다. **영향과 복구를 못 쓰겠으면 아직 풀 준비가 안 된
것이고, 프로덕션에서 알게 되는 대신 지금 스스로 알아낸 것입니다.** 그 판단이 세
줄에서 저절로 나옵니다. 그래서 사람한테 통하는 만큼 에이전트한테도 통합니다.

## 실제로 뭐가 좋아지나

**전부 리뷰하지 않아도 됩니다.**
밤새 에이전트가 34개를 커밋했습니다. 그중 둘에 UNFREEZE 줄이 붙어 있습니다.
그 둘을 먼저 읽으면 됩니다. 게이트가 에이전트를 신중하게 만든 게 아닙니다.
**어디서 길을 벗어났는지 스스로 말하게** 만든 겁니다.

**"간격 좀 고쳐"가 12개 파일로 돌아오지 않습니다.**
하나를 시켰는데 diff에는 그거 말고 세금 계산 리팩터링과, 상류 API가 불안정해서
있는 재시도 루프 "정리"가 같이 들어 있습니다. 에이전트가 부주의한 게 아닙니다.
**어떤 이상한 코드가 이유가 있어서 이상한지 구분할 방법이 없을 뿐입니다.**
이제 그 코드가 만져지는 순간 스스로 말합니다.

**뭘 받치고 있던 임시방편이 개선당하지 않습니다.**
어느 코드베이스에나 틀려 보이는데 뭔가를 받치고 있는 줄이 있습니다. 분기에 한
번쯤 누가 정리하고, 정리한 것과 연결되지 않는 방식으로 깨집니다.
`before_you_touch`가 그 울타리에 박힌 팻말이고, 아무도 안 여는 파일이 아니라
터미널에 뜹니다.

**자러 갈 수 있습니다.**
에이전트가 조심해져서가 아닙니다. 자는 동안 벌어질 수 있는 최악이,
**깨어 있을 때 당신이 쓴 목록으로 제한되기 때문입니다.**

**규칙이 누가 기억하느냐에 안 걸립니다.**
"모바일 레이아웃 건드리지 마"는 조언입니다. 안 통과되는 커밋은 정보입니다.
차이는 공손함이 아닙니다. 둘 중 하나는 새벽 3시에, 당신을 처음 보는 모델에게,
저장소에 들어온 첫 1분에 작동합니다.

## 이게 안 하는 것

얼마나 좋아지는지 재지 않습니다. 이 README에 벤치마크 표가 없는 건 정직하게 만들
방법이 없어서이고, 지어낸 표는 스크립트 두 개보다 가치가 없습니다.

시크릿이나 위험 패턴을 검사하지 않습니다. gitleaks와 semgrep이 여기서 만들
어떤 것보다 잘합니다. 이건 그쪽이 안 하는 걸 합니다.

에이전트가 코드를 더 잘 쓰게 만들지 않습니다. 틀린 변경이 나가기 전에 보이게
만듭니다. 다른 문제이고 이건 두 번째만 다룹니다.

리뷰를 대체하지 않습니다. 리뷰가 가장 못 잡는 종류를 없앨 뿐입니다. 이미 맞던
것에 대한 작고 그럴듯한 옆동네 수정 말입니다.

## 설치

```sh
git clone https://github.com/produckyou-design/agent-guardrails
./agent-guardrails/install.sh /path/to/your-repo
```

Windows:

```powershell
.\agent-guardrails\install.ps1 C:\path\to\your-repo
```

또는 `gates/*.py`를 `scripts/`에 복사하고, pre-commit 훅을 넣고,
`.github/workflows/gates.yml`을 추가하면 됩니다. 로컬 훅은 `--no-verify`로
넘길 수 있고 CI는 못 넘깁니다. 둘 다 두세요.

빈 동결 목록으로 시작하세요. 완성된 줄 알았던 걸 에이전트가 고치는 날 첫 경로를
넣으면 됩니다. 오래 안 걸립니다.

## 버티는 동결 항목 쓰는 법

이유 없는 경로는 다음에 필요한 사람이 그냥 풉니다. 동결을 버티게 하는 건
`what_breaks`입니다. 푸는 쪽이 무엇을 걸고 있는지 알아야 하니까요.

```json
{
  "label": "결제",
  "paths": ["src/billing/charge.py"],
  "reason": "완성돼서 운영 중이고 로드맵 어디에도 없다",
  "what_breaks": "계산이 틀려도 화면은 정상이고 금액만 달라진다",
  "before_you_touch": [
    "부분 환불은 여기가 아니라 refund.py가 소유한다",
    "실패하면 전체 트랜잭션을 되돌리는 설계다. 그걸 완화하지 않는다"
  ],
  "how_to_verify": "pytest tests/test_billing.py -q"
}
```

`before_you_touch`가 장애들이 들어가는 자리입니다. 여기 있는 줄은 전부 비싸게
배운 것이어야 합니다.

## 전부 잠그면 안 됩니다

동결이 저장소 전체에 걸리면 게이트가 늑대 소년이 되고, 잡음과 함께 진짜 위반도
무시됩니다. 로드맵이 곧 건드릴 경로는 비워 두세요.

이게 나온 프로젝트는 수백 개 중 19개만 잠급니다.

## 테스트

```sh
python tests/test_gates.py
```

16개입니다. 임시 디렉터리에 진짜 git 저장소를 만들고, 진짜 커밋을 하고,
게이트를 서브프로세스로 돌립니다. 목(mock)이 없습니다. 검증 대상이 게이트가
git을 어떻게 읽느냐이기 때문입니다.

비싸게 배운 버그도 들어 있습니다. `src/db/sync-notices.py`를 선언했더니 정규식이
하이픈을 먹어서 `src/db/sync_orders.py`까지 조용히 풀리던 것 같은 것 말입니다.

검증이 실행되는 코드여야 한다고 주장하는 저장소라면 자기 것도 증명할 수 있어야
합니다. 세 줄 규칙을 완화하면 3개가 실패하고, 하이픈 처리를 깨뜨리면 경로
테스트가 실패합니다. 해보세요.

## 같이 들어 있는 것

`FAILURE_MODES.md`에 이 게이트들이 나온 사건들이 있습니다. 쓸모 있게 만든 형식
그대로입니다.

```
증상  어떻게 보였나
원인  왜 그렇게 됐나
조치  무엇을 고쳤나
규칙  다음부터 어떻게 하나
```

들어갈지 판단하는 기준 하나. **이걸 안 적으면 다음에 또 할까?** 그렇다면 넣습니다.
아무것도 안 깨졌어도요. 반복되는 건 극적인 장애가 거의 아닙니다. 매번 걸어 들어가는
작은 고리들입니다.

`skill/SKILL.md`는 에이전트가 읽는 반쪽입니다. 게이트와 짝이 되는 운영 규칙입니다.
게이트는 기계적으로 검사 가능한 것을 잡고, 스킬은 나머지를 다룹니다. 실제로 돌린
검증에 대해 정직하게 보고하는 것 같은 것 말입니다.
